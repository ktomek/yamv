## Project Overview

YAMV (Yet Another MVI framework) is a Kotlin-first MVI (Model-View-Intent) architecture framework for Android with compile-time code generation via KSP. It provides reactive state management using Kotlin Coroutines and Flow, with optional Hilt DI integration.

## Commands

```bash
# Build
./gradlew build

# Run tests
./gradlew test

# Run tests for a single module
./gradlew :yamv:test
./gradlew :yamv-retainer:testDebugUnitTest

# Run a single test class
./gradlew :yamv:test --tests "com.ktomek.yamv.intention.FeatureRouterTest"

# Lint
./gradlew detekt

# Run detekt across all modules with HTML report
./gradlew detektAll
```

## Module Structure

- **`:core`** — Marker interfaces and annotations (`State`, `Outcome` hierarchy, `@AutoState`, `@AutoFeature`)
- **`:yamv`** — Core framework (pure Kotlin, no Android deps): `MviRuntime`, `MviStore`, `MviRegistry`, `FeatureRouter`, Feature wrappers
- **`:yamv-retainer`** — Lifecycle-retained MviStore: `MviRetainedStore`, `hiltMviStore()` Compose helper
- **`:processor-core`** — DI-agnostic KSP utilities: `AutoStateDiscovery`, `AutoFeatureDiscovery`
- **`:processor-hilt`** — Hilt-specific KSP processor: generates `*Store` retained stores and `*FeaturesModule` Hilt modules
- **`:app`** — Counter demo app showing framework usage end-to-end

## Architecture

### MVI Data Flow

```
Composable UI
  → dispatches Intentions (sealed classes)
*Store (MviRetainedStore subclass, generated by @AutoState)
  → routes via FeatureRouter
Features (Set<Feature<S>>, injected by Hilt multibindings)
  → emit Outcomes
MviRuntime splits outcomes into:
  - StateOutcome (Reducer): pure (S) -> S transformations, accumulated via scan
  - EffectOutcome: side effects
  - IntentionOutcome: dispatch new intentions (chaining/recursion)
StateFlow<S> (observed by UI)
```

### Key Abstractions

**Outcomes** (`core/Outcome.kt`):
- `StateOutcome<S>` — SAM type: `(prevState: S) -> S`
- `EffectOutcome<S>` — side effect marker
- `IntentionOutcome<S>` — triggers another intention dispatch

**Features** — three levels of abstraction:
- `Feature<S>` (sealed) — low-level, untyped `Flow<Any> → Flow<Outcome<S>>`
- `TypedFeature<S, I>` — typed intentions `Flow<I> → Flow<Outcome<S>>`; use `.wrap()` to convert to `Feature<S>`
- `FunctionTypedFeature<S, I>` — single-intention handler `(I) -> Outcome<S>`; use `functionTypedFeature<S, I> { }` builder

**Dispatcher Strategy** (`CoroutineDispatcherConfig`):
- Intentions & Reducers → `Dispatchers.Main`
- Features → `Dispatchers.Default`

**MviStore lifecycle**:
- `MviRuntime` owns its own `CoroutineScope(SupervisorJob() + ...)` — no parent scope dependency
- Terminated via `clear()`, called automatically by `MviRetainedStore.onCleared()`

### Code Generation

Annotate a state class with `@AutoState` to generate `{StateName}Store` (a `@HiltViewModel` subclass of `MviRetainedStore`).

Annotate feature classes/properties with `@AutoFeature` to generate `{StateName}FeaturesModule` (Hilt multibindings providing `Set<Feature<S>>`).

**Dagger constraint**: `@Binds` (abstract) methods go in the interface body; `@Provides` + `.wrap()` methods go in the companion object.

### Exception Handling

`MviExceptionHandler` controls what happens when a feature or reducer throws. Default: rethrow + cancel scope (fail-fast). Custom handlers can log/report before rethrowing, or opt into degraded mode by not rethrowing.

- `MviExceptionHandler.Default` — rethrows, cancels the entire scope
- `MviErrorContext` — carries `ErrorSource` (`REDUCER`, `FEATURE`, `EFFECT`, `INTENTION_REDISPATCH`), optional `intention` and `feature` references
- Pass via `MviRuntime(features, defaultState, exceptionHandler = ...)` or the factory function

### Coroutine Safety

`FeatureRouter` uses `CompletableDeferred` to ensure all features are subscribed before the first intention is dispatched. `MviRuntime` manages three independent coroutine collectors (reducers, effects, intention re-dispatch) and is cancelled via `clear()`.

## Testing

Tests use JUnit 5, MockK, Turbine (Flow testing), and Truth assertions. See `yamv/src/test/` for examples.

Android unit tests (`:yamv-retainer`) require `testOptions { unitTests.all { it.useJUnitPlatform() } }` in the module's `build.gradle.kts`.
