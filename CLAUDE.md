## Project Overview

YAMV (Yet Another MVI framework) is a Kotlin-first MVI (Model-View-Intent) architecture framework for Android with compile-time code generation via KSP. It provides reactive state management using Kotlin Coroutines and Flow, with Hilt DI integration.

## Commands

```bash
# Build
./gradlew build

# Run tests
./gradlew test

# Run tests for a single module
./gradlew :yamv:test
./gradlew :app:test

# Run a single test class
./gradlew :yamv:test --tests "com.ktomek.yamv.intention.DefaultIntentionDispatcherTest"

# Lint
./gradlew detekt

# Run detekt across all modules with HTML report
./gradlew detektAll
```

## Module Structure

- **`:core`** — Marker interfaces and annotations (`State`, `Outcome` hierarchy, `@AutoState`, `@AutoFeature`)
- **`:yamv`** — Core framework: `StateContainer`, `StateContainerHost`, `DefaultIntentionDispatcher`, Feature wrappers
- **`:processor`** — KSP processor that generates `*ContainerHost` ViewModels and `*FeaturesModule` Hilt modules
- **`:app`** — Counter demo app showing framework usage end-to-end

## Architecture

### MVI Data Flow

```
Composable UI
  → dispatches Intentions (sealed classes)
StateContainerHost (ViewModel, generated by @AutoState)
  → routes via DefaultIntentionDispatcher
Features (Set<Feature<S>>, injected by Hilt multibindings)
  → emit Outcomes
StateContainer splits outcomes into:
  - StateOutcome (Reducer): pure (S) -> S transformations, accumulated via scan
  - EffectOutcome: side effects
  - IntentionOutcome: dispatch new intentions (chaining/recursion)
StateFlow<S> (observed by UI)
```

### Key Abstractions

**Outcomes** (`core/Outcome.kt`):
- `StateOutcome<S>` — SAM type: `(prevState: S) -> S`
- `EffectOutcome<S>` — side effect marker
- `IntentionOutcome<S>` — triggers another intention dispatch

**Features** — three levels of abstraction:
- `Feature<S>` (sealed) — low-level, untyped `Flow<Any> → Flow<Outcome<S>>`
- `TypedFeature<S, I>` — typed intentions `Flow<I> → Flow<Outcome<S>>`; use `.wrap()` to convert to `Feature<S>`
- `FunctionTypedFeature<S, I>` — single-intention handler `(I) -> Outcome<S>`; use `functionTypedFeature<S, I> { }` builder

**Dispatcher Strategy** (`YamvDispatcherProvider`):
- Intentions & Reducers → `Dispatchers.Main`
- Features → `Dispatchers.Default`

### Code Generation

Annotate a state class with `@AutoState` to generate `{StateName}ContainerHost` (a `@HiltViewModel`).

Annotate feature classes/properties with `@AutoFeature` to generate `{StateName}FeaturesModule` (Hilt multibindings providing `Set<Feature<S>>`).

### Coroutine Safety

`DefaultIntentionDispatcher` uses `CompletableDeferred` to ensure all features are subscribed before the first intention is dispatched. `StateContainer` manages three independent coroutine collectors (reducers, effects, intention re-dispatch) and is closed in `StateContainerHost.onCleared()`.
